1. **Phase 1 — `account_id` split + multi-account routing** — DONE. Root-cause bug: `state.monzo.account_id` was used as BOTH the Monzo fetch id AND the Actual import id, so transactions imported into a non-existent Actual account ("added without an account"). Fixed by splitting into per-account `AccountLink { monzo_id, monzo_name, actual_id, actual_name }` in `state.monzo.accounts`; Monzo fetches per account (tags `RawTransaction.source_monzo_id`); `run` groups imports by resolved Actual account and imports once per account; unmapped/ambiguous source → HELD (fail-loud, never dropped — including resolved reviews, which re-hold). 2. **Phase 2 — categories** — **DONE 2026-06-03**, merged to `main` locally (fast-forward, **NOT pushed to origin**). Claude classifies each merchant into one of the user's existing Actual categories in the SAME combined call as the payee (`Classification { payee, payee_confidence, category, category_confidence }`, trait `classify`). A txn auto-imports only when BOTH dimensions are confident AND resolve to live entities; else HELD with a **two-dimension** review state — each `PendingReview` now has a payee dimension (settled via `resolve_to`/`create_new`) and a category dimension (`category_resolved`/`resolve_category_to`/`category_suggestion`); `take_resolved` imports only when BOTH settle. Telegram review is **sequential**: payee prompt first (if uncertain), then category (`cc`=confirm/`xc`=skip category codes); `poll` clears `telegram_message_id` on the payee→category transition to re-prompt. Separate `category_cache` (raw→category name) beside `payee_cache`; a merchant skips Claude only if BOTH caches hit. Fail-loud throughout: stale/ambiguous cached or resolved category → re-hold with payee pre-settled + category re-prompted (never silently uncategorised). Degrades to Phase-1 (uncategorised, no prompts) when the user has zero Actual categories. **CORRECTED API FACT (this memory was wrong before):** the `importTransactions` transaction field for the category is **`category`** (holds the category **id**), NOT `category_id` — verified against the INSTALLED `@actual-app/core` `ImportTransactionEntity` type (docs misleadingly show `category_id`). `getCategories()` returns groups+categories mixed; real categories have a `group_id` (the shim filters on it). Spec `docs/superpowers/specs/2026-06-03-categories-design.md`, plan `docs/superpowers/plans/2026-06-03-categories.md`.
