When editing Rust in this harness, three environment behaviours recur and waste time if not anticipated:

1. **`<new-diagnostics>` (rust-analyzer/rustc) are frequently STALE — do not trust them.** They are captured mid-edit and routinely report false "cannot find type / method not found / N arguments expected" errors that the real toolchain contradicts. Throughout the aba Phase 1 build, almost every subagent edit produced alarming diagnostics while `cargo build`/`clippy`/`test` were clean. **Root cause (diagnosed 2026-06-02):** these were pushed by **Claude Code's built-in `rust-analyzer-lsp` plugin** (NOT Serena — Serena only emits diagnostics via its `get_diagnostics_for_file` tool when called). The plugin auto-pushes ~150ms after each edit, snapshotting invalid intermediate states (known issue claude-code#17979). **Fix applied:** the plugin is now **disabled globally** (`rust-analyzer-lsp@claude-plugins-official: false` in `~/.claude/settings.json`; takes effect next session), so future sessions should not see these for Rust. Cross-project guidance lives in `~/.claude/includes/rust.md`. For an on-demand LSP signal use Serena's pull-based `get_diagnostics_for_file`; cargo remains source of truth.

2. **A global semgrep PreToolUse hook blocks certain writes.** It flags `std::fs::*` calls as `tainted-path` and Dockerfiles that run as root (CWE-269/250). It is NOT repo-local config — it fires across projects.

3. **Windows `std::process::Command` cannot spawn `.cmd`/`.bat` directly** (CreateProcess + post-BatBadBut). Tests that need a fake child process must invoke a real executable.

4. **`aba` is a BINARY crate with no lib target — `cargo test --lib` (and `--lib <filter>`) FAILS with "no library targets found".** Use `cargo test` (or `cargo test <name>` to filter). The Phase 1/2 plan docs repeatedly wrote `cargo test --lib <module>`; every subagent tripped on it. Tell subagents to use `cargo test` up front.

5. **Clippy enforces pedantic + nursery** (changed 2026-06-02; previously default-only). The lint policy lives in **`[lints.clippy]` in `Cargo.toml`** (the single source of truth: groups `all`/`pedantic`/`nursery` at `level=warn, priority=-1`, plus the standard allow-list). CI (`.github/workflows/release.yml`) runs `cargo clippy --all-targets -- -D warnings`, which promotes those warn-level lints to hard ERRORS — so pedantic/nursery findings (`derive_partial_eq_without_eq`, `doc_markdown`, `format_push_string`, `option_if_let_else`, `assigning_clones`, …) DO fail the build; fix them, don't ignore them. The same `[lints.clippy]` block is the global standard for every Rust project (see `~/.claude/includes/rust.md` + global `CLAUDE.md`); the `~/.claude/hooks/clippy.sh` edit hook auto-detects a `[lints]` table and runs bare clippy to honour it. **Remediate** with `cargo clippy --fix --allow-dirty --all-targets` first (auto-fixes most), then hand-fix the rest; for unavoidable ones use a local `#[allow(clippy::x)]` + one-line reason. **Gotcha:** a statement-level `#[allow(clippy::significant_drop_tightening)]` on a `let guard = …lock().unwrap();` does NOT suppress that nursery lint — use an explicit `drop(guard);` after the guard's last use (or a function-level allow). (During incremental multi-commit work, `dead_code` on not-yet-wired items is still expected and clears once the consuming task lands; per-task check is `cargo test`, full clippy gate runs last. **Binary-crate specific (recurred 3× in Phase-1 multi-account work):** because `aba` is a bin crate with no public API, even `pub fn`/`pub struct` items trip `dead_code` under `-D warnings` until something CALLS them — and `#[cfg(test)]` usage does NOT suppress it for the bin target. When a task adds an item the NEXT task will consume, put a scoped `#[allow(dead_code)] // wired up in Task N` on it and have Task N remove the allow. Don't try to satisfy it with a test alone.)

6. **The PostToolUse Rust formatter hook reorders `use` imports CASE-INSENSITIVELY, which CONFLICTS with this repo's edition-2024 `cargo fmt`.** After every `Edit` tool call the hook rewrites e.g. `use anyhow::{Result, anyhow};` → `use anyhow::{anyhow, Result};` (lowercase-first), but edition-2024 `cargo fmt` (and CI) want ASCII order `{Result, anyhow}` (uppercase first). So an `Edit` that touches a multi-item `use` line lands the crate in a state that **fails CI's `cargo fmt --all -- --check`** — even though `cargo build`/`clippy`/`cargo test` are all green. This cost a review cycle in the Phase-1 multi-account work (2026-06-03): the build gates passed, but the committed `config.rs` import was in the hook's order and would have failed CI. **Two compounding traps:** (a) standalone `rustfmt --check <file>` defaults to edition 2015 and PASSES the hook's order, masking the problem — only `cargo fmt` (which reads the repo's edition-2024 config) catches it; (b) the plan's per-task verification gates were build+test+clippy and did NOT include `cargo fmt --all -- --check`, so several earlier commits also drifted (long `anyhow!` calls left un-wrapped). **RESOLVED 2026-06-03 (root cause fixed):** the culprit was the global PostToolUse formatter `~/.claude/hooks/format-code.sh` (a symlink into `dotfiles/ai/hooks/`), whose `rs)` branch ran **bare `rustfmt`** — defaulting to edition 2015. Fixed it to read the crate edition from the nearest `Cargo.toml` and pass `rustfmt --edition <ed>`, so single-file formatting now matches `cargo fmt`/CI on every Rust project on this machine (verified: bare→`{anyhow, Result}`, `--edition 2024`→`{Result, anyhow}`). The change lives in the dotfiles repo (`ai/hooks/format-code.sh`, shows as modified) — **commit it there, and re-apply if a dotfiles reset reverts it.** **Residual good practice (keep doing this regardless):** still add `cargo fmt --all -- --check` to every Rust task's verification gate alongside build/test/clippy — the plan's gates omitted it and several commits drifted before the hook fix; and for any belt-and-braces commit, a final Bash `cargo fmt --all` before committing is harmless and authoritative.

7. **Windows working-tree hazards during multi-subagent runs (both hit 2026-06-03, Phase-2 categories).** (a) **Subagent Bash piping to `tee /tmp/x.txt` mangles on this box** into literal junk files named `C<fullwidth-colon>Temp…txt` in the REPO ROOT (untracked). Don't tell subagents to `tee /tmp/...`; have them run `cargo test 2>&1` and read the tail, or redirect to a repo-relative file they then `rm`. (b) **`.serena/memories/` is UNTRACKED**, so `git clean -fd` (used to sweep those junk files) silently DELETES it. Never `git clean -fd` here — `rm` the specific junk files by name instead. (c) Non-isolated subagents share ONE working tree, so a subagent that runs `git checkout main`/`git clean` affects everyone; one Phase-2 subagent was found mid-run on `main` and had to switch back. If parallel isolation matters, spawn with `isolation: "worktree"`; otherwise tell subagents to confirm `git rev-parse --abbrev-ref HEAD` and never checkout/clean. **Refinement (Phase-4 telegram-grouping, 2026-06-04):** the tree DRIFTED to the PRIOR session's branch (`feat/transfers`) repeatedly across sequential dispatches even though no subagent ran `checkout` — so "never checkout" isn't enough on its own. The effective fix that ran 7 tasks cleanly: **begin every subagent prompt with an explicit guard — "FIRST run `git branch --show-current`; if it isn't `<feature-branch>`, `git checkout <feature-branch>` before doing anything"** — i.e. each subagent recovers the branch rather than assuming it. Also confirm the branch yourself between dispatches (`git branch --show-current` + `git log --oneline`).

   **Fan-out tactic that worked well for MECHANICAL edits (Phase-C test-call-site fixes, 2026-06-11):** when a refactor leaves dozens of identical mechanical fixes across files, get the crate's PRODUCTION code green yourself first, then dispatch one PARALLEL subagent PER FILE (give each a precise transform spec + the file's error line list). Two rules make it clean on the shared tree: (i) assign DISJOINT files so edits never collide; (ii) tell subagents **NOT to run `cargo`** — parallel cargo invocations contend on the single `target/` build lock (and a subagent compiling mid-edit sees the others' in-progress errors) — instead YOU compile centrally ONCE after they all report. Ran 2 agents (~50–80k tokens each) over `monzo.rs` + `pipeline/mod.rs` with zero residual errors. Background (`run_in_background: true`) lets you fix the small files yourself while they run.

8. **Two lint/serde traps from the Phase-A remediation (2026-06-10), each cost a subagent round-trip:** (a) **`#[serde(default)]` on an `Option<T>` field of a GENERIC struct makes serde's derive emit a `T: Default` bound** (the derive is conservative; it doesn't know `Option<T>: Default` holds for all T) — breaks when T (e.g. `Vec<Payee>`) isn't Default. Fix: `const fn none<T>() -> Option<T> { None }` + `#[serde(default = "none")]` (standard workaround; used in `shim_protocol.rs::ShimResponse`). (b) **`pub(crate)` inside a PRIVATE module of this bin crate trips nursery `redundant_pub_crate`** (plain `pub` is already crate-bounded there, so the lint is right); if a spec insists on `pub(crate)`, it needs `#[allow(clippy::redundant_pub_crate)]` + reason — better to just use `pub` and note why. Don't let reviewers flag `pub` as "too wide" in private modules of this crate. (c) **A serde `#[serde(with = "mod"]` adapter's `serialize` fn trips pedantic `clippy::ref_option`** (it wants `Option<&T>` not `&Option<T>`), but serde's `with` contract FIXES the signature to `fn serialize(&Option<T>, S)` — `Option<&T>` won't satisfy it. Annotate the fn with `#[allow(clippy::ref_option)]` + one-line reason; don't try to "fix" the signature. (Hit in Phase-C `ids::opt_actual_empty`, 2026-06-11.)

**Why:** Acting on stale diagnostics sends you chasing phantom compile errors; fighting the semgrep hook with rustfmt re-wrapping the `nosemgrep` comment derails a task; assuming `.cmd` is spawnable makes a test that can never pass on this machine; `--lib` wastes a round-trip on a binary crate; and since pedantic/nursery are now in the gate, ignoring them (or hardcoding clippy flags instead of using `[lints.clippy]`) breaks CI or lets the layers drift.

**How to apply:**
- After any Rust edit, verify with `cargo build` / `cargo clippy --all-targets -- -D warnings` / `cargo test` and read the ACTUAL output (grep for `error[`/`FAILED`); treat `<new-diagnostics>` as advisory only.
- When semgrep flags an `std::fs`/path call, put it on its own `let` line and append `// nosemgrep: rust.actix.path-traversal.tainted-path.tainted-path` (the recurring rule id) with a one-line justification. For Dockerfiles, add `USER node` (or a non-root user) before `ENTRYPOINT`. Tell subagents this up front.
- Run tests with `cargo test`, never `--lib`.
- In review, pedantic + nursery ARE in the gate — fix them (or `#[allow]` with a reason). The lint config is `[lints.clippy]` in `Cargo.toml`; never re-add clippy lint flags on the command line.
- For tests needing a fake shim/child, point at a real executable (e.g. `node` running a tiny throwaway script) rather than a shell `.cmd`. See [[server-constraints]] for the deployment side.
- Include `cargo fmt --all -- --check` in every Rust task's gate (the format hook is now edition-aware as of 2026-06-03, but the gate is the real guarantee); never trust standalone `rustfmt --check` to judge CI-fmt (it defaults to edition 2015). See [[multi-account-routing-phase1]].
